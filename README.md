# Branching RPG

故事剧情为主的分支选择 RPG。项目采用“内容数据驱动”结构：剧情作者主要编辑 `content/`，游戏运行时负责解析节点、维护状态并展示选择。

## 主要结构

```text
RPG/
├─ README.md                 # 项目说明与约定
├─ docs/
│  ├─ architecture.md        # 模块边界与运行流程
│  └─ content-authoring.md    # 剧情编写规范
├─ content/
│  ├─ chapters/               # 按章节拆分的剧情文件
│  ├─ characters/             # 角色定义、立绘/标签引用
│  ├─ locations/              # 地点与场景定义
│  └─ localization/           # 多语言文本（预留）
├─ src/
│  ├─ core/                   # 与表现层无关的游戏逻辑
│  │  ├─ story/               # 节点解析、条件、选择、跳转
│  │  ├─ state/               # 玩家状态、变量、关系值、旗标
│  │  └─ save/                # 存档/读档接口
│  ├─ presentation/           # UI、输入、动画、音频适配层
│  └─ main/                   # 平台入口与依赖组装
├─ assets/
│  ├─ art/                    # 立绘、背景、CG、图标
│  ├─ audio/                  # BGM、音效、语音
│  └─ fonts/
├─ tests/                     # 核心规则与剧情校验测试
└─ tools/                     # 剧情校验、导入导出等编辑工具
```

## 核心设计

- **剧情节点**：每个节点只描述文本、演出提示和可选出口，不直接依赖 UI。
- **条件与效果**：选择可读取状态条件，并在跳转前应用变量、旗标、关系值等效果。
- **状态集中管理**：剧情节点不自行持久化；所有变化通过 `GameState` 进入存档系统。
- **内容可校验**：节点 ID 必须唯一，目标节点必须存在，条件和效果使用白名单操作。

## 当前示例

`content/chapters/chapter-01.json` 包含一个最小的开场、两项选择和两个结局节点，用于验证内容格式。
